# Team rules

How heinzelwerk agents work in this repo. Mode rules (single repo vs workspace) live in the `heinzelwerk:team-modes` skill. This file holds only what is specific to this repo.

- **Autonomy**: full. Agents merge and apply on their own; breakages are learnings. Secrets are never published (name the variable, never the value), and the gate never merges its own policy.
- **Backend paths**: whole repo (`src/`, `scripts/`, `contract/`)
- **Worktree setup**: `npm ci --ignore-scripts`
- **Checks** (copied from `.github/workflows/container.yml`, jobs `ts-checks`, `test`, `contract`, in order):
  - `npm run check:deps`
  - `npm run typecheck`
  - `npm run lint`
  - `npm run build`
  - `npm run openapi && test -z "$(git status --porcelain -- openapi.json)"`
  - `npm test`
  - `docker build -t auth-service:contract .` (unverified locally: docker daemon not running)
  - The `contract` job's probe "The image's Node is at least 24.15 and it runs as root": `docker run --rm auth-service:contract -e '<script from container.yml>'` (unverified locally: docker daemon not running)
  - `cd contract && npm ci --ignore-scripts && npm run typecheck`
  - `CONTRACT_IMAGE=auth-service:contract node scripts/run-contract.cjs` (unverified locally: needs the image)
  - CI also runs `npm audit --audit-level=high` in `ts-checks`; it is red on main (V-M-Pioneer-Trading/meta#119) and left out here by owner decision until that ticket closes, so CI on a PR is red for that step alone.
- **Checks verified on main**: 2d25f28 2026-10-28
- **Coding standards**: `@v-m-pioneer-trading/eslint-config` base (`eslint.config.mjs:5`); invariants and "Deliberate differences from Go" in `CLAUDE.md`
- **Risk areas** (validator reviews diffs touching these on Opus). This repo holds the game token, the account token and the Clerk keys; treat every diff as security work:
  - `src/vault.ts`, `src/controllers/vault.controller.ts`: `GET /auth/v1/token` hands the game token to st-gateway on `X-Auth-Service-Secret`; never routed publicly
  - `src/introspection.ts`, `src/jwt/**`, `src/keys.ts`: the center, the only token verifier in the workspace (auth-design decision 21)
  - `src/m2m/**`: mints Clerk M2M tokens against api.clerk.com (`src/m2m/clerk.ts`); caller secret = caller identity
  - `src/controllers/operator.controller.ts`: `POST /api/auth/v1/agent-token` and /register (scope `agent:reset`) reset the game account; the production probe never calls them
  - `src/poller.ts`: re-registers the agent by itself when SpaceTraders' `resetDate` changes
  - `src/db/schema.ts`: DDL stays byte-identical to the Go service so a rollback image opens the same file
  - `contract/**`: never edited to make code pass; `contract-skip.txt` stays empty
  - Logging anywhere: credentials are never logged or echoed
  - `.github/workflows/container.yml`: a merge to main deploys to production; job names `ts-checks`, `test`, `contract` are required checks
- **Contracts** (see team-modes **Contract changes**):
  - API: `openapi.json` (generated by `npm run openapi`) · provider auth-service; mirrored to `../meta/openapi/auth-service.json`
  - Provided: `GET /auth/v1/token` (st-gateway), `POST /auth/v1/introspect` (agent-, automation-, fleet-, navigation-service, st-gateway, through clerk-client or their own client), `POST /auth/v1/m2m-token` (automation-service, ai-service), scope literals (`../meta/docs/design/auth-design.md` decisions 2, 20, 22)
  - Vendored: `contract/fixtures/introspection.json`, copy of `../meta/fixtures/introspection.json`, pinned in `contract/fixtures/SOURCE.txt` · provider meta; a provider change means a re-vendor here
  - Infra outputs: the auth-service stack's outputs (SSM parameter names) are read by every other stack through `terraform_remote_state` · provider infrastructure (`../V-M-Pioneer-Trading_infrastructure/auth-service/outputs.tf`)
