go-written.db
  A SQLite file written by the Go service's own `db` package (src/db at the commit this was made from, modernc.org/sqlite
  v1.34.4, Go 1.22.4), by the program in go-writer.go.txt: SetUpDatabase, UpsertCredential (symbol GO_WRITTEN; the reset
  date with a +02:00 offset, the predicted reset in UTC), two AppendHistory rows, SetTokenExpired(true). Every value is an
  obvious placeholder, no credential. `db.test.ts` checks the sha256 below, opens it with node:sqlite, reads the row,
  and compares its DDL with the one this service applies: the schema does not change in the port, so a rollback to the
  Go image opens the same file.
  sha256 9ca9d183c8fb4b74f36c97eb711705360de01da6c82f4fc12a6d2e036e52f806

  To remake it (Go on the PATH; from a scratch module that replaces vnm/auth-service with the repository's src/):
    SQLITE_DB_PATH=out.db GOFLAGS=-mod=mod go run .

go-verdicts.json
  What the Go service's parsing functions answer on a corpus, recorded by running them (go 1.22.4):
  url      clerkURLFromEnv (src/api/m2m.go): "refused", or "ok scheme://host -> mint endpoint"
  times    parseTime (src/db/credential.go): time.Parse(time.RFC3339, s).Format(time.RFC3339) and the Unix milliseconds, or "zero"
  spaces   every code point (up to U+3100 and a few above) that strings.TrimSpace strips
  keys     golang-jwt v5.3.1 ParseRSAPublicKeyFromPEM / ParseRSAPrivateKeyFromPEM, by the case names of
           src/testSupport/keyCases.ts (the keys are generated per run, so no private key is committed)
  The tests in goUrl.test.ts, goTime.test.ts, goText.test.ts and keys.test.ts hold the TypeScript readers to them.

  The "jwt", "mediaTypes" and "queries" sections and the key cases added in step 7b were recorded by go-recorder.go.txt
  (Go 1.22.4, golang-jwt v5.3.1; the program, and the Go service's verifyToken in it verbatim but for a fixed clock):
  jwt         src/api/introspect.go's verifyToken plus writeIntrospection, at nowMs, by the case names of
              src/testSupport/jwtCases.ts: the exact body Go writes (verifyToken.test.ts)
  mediaTypes  mime.ParseMediaType of src/testSupport/formCases.ts's Content-Type values: the media type and whether it
              failed (goParity.test.ts)
  queries     url.ParseQuery of its query strings: every key's values (hex of the bytes, keys sorted) and whether it
              failed (goParity.test.ts)
  To re-record (Go and Node 24 on the PATH), in a scratch directory:
    cp <this dir>/go-recorder.go.txt main.go && cp <this dir>/go-recorder-input.mjs.txt go-recorder-input.mjs
    go mod init recorder && go get github.com/golang-jwt/jwt/v5@v5.3.1
    node go-recorder-input.mjs <ts>/src/testSupport > input.json && go run . input.json > output.json
  then merge output.json into go-verdicts.json (keys by name; jwt.answers by name with nowMs from input.json; the
  mediaTypes and queries as [input, verdict] pairs in case order). Keys and tokens are generated per run: the verdicts
  depend on neither, and no private key or signed token is committed.

  go-m2m-recorder.go.txt (Go 1.22.4; golang.org/x/net v0.19.1-0.20240412193750-db050b07227e and golang.org/x/text
  v0.14.0, the revisions Go 1.22.4 vendors into net/http):
  tokens   src/api/m2m.go's cacheEntryFrom, verbatim, at nowMs: "ok <expiresAt> <refreshAt>" or "refused"
  bodies   the end of its clerkMinter, verbatim: json.NewDecoder(io.LimitReader(body, 64<<10)).Decode then the empty

  changed corpus without a re-recording fails. To re-record (Go and Node 24 on the PATH), in a scratch directory:

    node go-m2m-recorder-input.mjs <ts>/src/testSupport > input.json && go run . input.json > go-m2m-verdicts.json
